# 项目完整指南

## 项目定位

本项目是个人本地内容整理平台，当前以 B 站已关注 UP 主为唯一正式内容源。它把关注列表转成可筛选、可分类、可复盘的内容资产。

## 使用流程

1. 启动后端并打开网页。
2. 在数据接入页扫码登录 B 站。
3. 启动全量同步，后台读取全部关注 UP 主。
4. 每位 UP 主抓取最新 5 条公开视频。
5. 通过视频详情接口补齐互动数据。
6. 运行规则分析，生成主题、周更、热度、活跃度和质量。
7. 在总览、主题弹窗、趋势弹窗和博主详情中查看结果。

## 运行逻辑

前端只负责展示和发起操作；后端负责登录状态、B站 API 请求、数据库写入、去重和分析。所有账号和视频数据都进入本地 SQLite。

同步过程分为：读取关注列表、预写入账号、读取视频、分批入库、合并重复账号、运行分析、写入同步历史。任何单个 UP 主请求失败都会跳过并继续，最终在同步状态中保留结果。

## 指标定义

| 指标 | 计算方式 |
|---|---|
| 热度 | 粉丝量 45% + 发布量 25% + 近 7 天活跃度 30% |
| 活跃度 | 当前日期之前 7 天发布的视频数量归一化 |
| 质量 | 最近视频平均点赞数在有样本账号中归一化 |
| 周更 | 当前时间往前 7 天的视频数量 |
| 主题 | 最近 5 条视频标题和简介的关键词得分 |

## 故障排查

### 页面打不开

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen
```

没有监听时使用项目 `.venv` 启动：

```powershell
.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

### 全量同步失败

1. 检查 `GET /api/bilibili/status`。
2. 重新扫码登录。
3. 确认网络能访问 `api.bilibili.com`。
4. 等待上一轮任务结束后再重试。

### 点赞数据不足

在“数据接入”点击一次“补齐点赞数据”。该任务会按 BV 号调用视频详情接口，并在完成后自动重新分析。不要在任务运行时重复点击。

### 数据重置

删除本地 `data/creator_manager.db` 前请先导出结果。删除数据库会清除账号、视频、人工修正和同步历史，无法从远程仓库恢复。
